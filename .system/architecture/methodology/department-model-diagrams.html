The Department Model in one paragraph
Read this first. Everything else is detail.
The Department Model is a way to build agentic systems where each agent acts like a department in a small, specialized firm. The firm has a studio (a domain), staffed by specialists (atomic skills with one job each), coordinated by a studio director (an orchestrator that routes work and holds the firm's vocabulary), governed by partners (critic skills that review specialist output against the firm's values), and organized around engagements (long-running projects with intake, phases, gates, and deliverables) whose state lives in a filing system (a state file plus a raw/ directory) that any specialist can read and write. The firm's identity, voice, ethics, and quality bar live in a constitution that every partner consults before approving any work. Communication between the firm and the outside world happens through briefs (commands), written in markdown and executed by the model itself. The whole system runs on prose: every artifact — orchestrator, specialist, brief, constitution, gate — is a markdown file the model reads and acts on.

The Engagement Lifecycle
Intake · phases · gates · delivery — with iteration on gate failure

Phases run linearly. Gates iterate (capped at three). A gate failure routes back to the most recent producing phase, not back to the start of the engagement.

Every artifact is written to the engagement file (the project manager) plus the raw/ directory (the filing cabinet). State references files; files are timestamped and never overwritten. The engagement is fully resumable from any point by reading state.phases.{phase}.status.

The Gate Mechanism
How a quality review actually runs · the firm's governance pattern

Every gate (A, B, C, silo) follows the same shape: pre-flight load → cross-model scoring → verdict → iterate-or-escalate. Pre-flight is non-negotiable; same-model self-critique fails before scoring; iteration caps at three.

① Pre-flight load
Load constitution (10 articles) · Load state.intake (the brief) · Load voice spec · Article 6: verify intake citations
▼
② Generator
Default: Sonnet · produces the work (brief, plan, post)
→
③ Critic — different model
Default: Opus · Article 7: hard-fails if same model · scores against constitution articles
▼
④ Verdict
Score ≥ threshold + every Hard-Fail article passed → PASS, advance to next phase · else → fail with cited findings
Article 8 — Iteration cap: on fail, re-do producing phase 1 2 3 then escalate to human. Reflexion (Shinn et al., 2023): diminishing returns past 3–5 iterations. We choose conservative.
▼
⑤ Escalation (after iteration 3)
Engagement halts · findings surfaced to the user with full audit trail · human decides whether to revise the brief, accept partial output, or kill the engagement.

When to use which framework
The Department Model vs LangGraph, CrewAI, AutoGen, AutoGPT, MCP

No framework wins on every dimension. The Department Model is best for long-horizon, document-driven, file-based, briefed creative knowledge work. For other shapes, choose differently.

If your work is… Best fit
Long-horizon document work (hours to weeks) Department Model
Telegram or chat-driven engagement intake Department Model
Pipelines that need to be legible to non-engineers Department Model
Iteration speed on the pipeline itself matters Department Model
Production reliability + type-safe state required LangGraph
Hierarchical pipeline with explicit graph branching Department Model or LangGraph
Emergent multi-agent collaboration (creative debate, exploration) CrewAI
Conversation-as-coordination is the primary primitive AutoGen
Open-ended autonomous task generation (research, exploration) AutoGPT-class
Tool integration only (not orchestration) MCP + plain function calling
Real-time low-latency responses (sub-second) None of the above
Heavy concurrent state mutation (live trading, RTB) Use a proper database
Strict transactional guarantees (medical, financial settlements) Domain-specific infra
The underlying disagreement: The agentic-AI ecosystem splits between "agents are software, organize them with frameworks" (LangGraph, CrewAI, AutoGen) and "agents are knowledge workers, organize them with conventions" (Department Model, just-prompts schools). Neither is wrong. Choose the camp whose philosophy fits the work.
